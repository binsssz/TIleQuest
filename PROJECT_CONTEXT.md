# Project Context for AI Agents

## Project at a glance

- **Name:** TileQuest — Forest Village RPG.
- **Purpose:** C# / MonoGame DSA course project.
- **Current state:** Playable village, forest, and dungeon prototype with map travel and basic melee combat. DSA utilities are mostly standalone and are verified by startup self-checks.
- **Target framework:** .NET 8 (`net8.0`).
- **Game framework:** `MonoGame.Framework.DesktopGL` 3.8.x.
- **Project file:** `TileQuest.csproj`.

## Current behavior

- `Game1` creates a 48 × 36 village, 36 × 29 forest, and 36 × 28 dungeon. All use 32-pixel world tiles.
- Village collision comes from `VillageCollisionLayout` in `CollisionMapLayouts.cs`. The village is rendered as the ground and transparent object layers (`Content/village_ground.png` and `Content/village_objects.png`), with separately drawn structures and wizard.
- Forest collision comes from `ForestLayout.Rows` in `forestlayout.cs`, generated by `ForestGenerator`. Its fixed ground and canopy art are `Content/forest_ground.png` and `Content/forest_canopy.png`. Canopy art renders over the player. The forest-to-dungeon entrance triggers on the three tiles x=30–32, y=15; its center point `(31, 15)` is also the dungeon return point. The forest gate at `(18, 17)` returns to the village.
- Dungeon collision comes from `DungeonCollisionLayout` in `CollisionMapLayouts.cs`. `Content/dungeon.png` is drawn as its background, with a screen-space vignette. Its exit leads back to the forest entrance.
- Travel from the village is requested with `E` while next to the wizard. Stepping on a travel tile requests the corresponding map transition. Confirm with `Y` or `Enter`; cancel with `N` or `Escape`. Prompts are drawn at the bottom center.
- Movement is four-directional, grid-locked, smoothly interpolated, and collision checked. The camera follows the player.
- `Space` or `J` performs a melee swing. Training enemies are stationary targets around map spawn points; they can be damaged, knocked back, and defeated, but do not pursue or attack.
- A screen-space HUD shows red health and blue energy bars at the lower left and a 4 × 2, Minecraft-style inventory grid at the lower right. The bars are currently visual-only; player health and energy mechanics are not implemented.
- `F3` toggles the hitbox/debug overlay.
- Startup runs `TileGraph` connectivity checks and `DsaDemo` self-checks.
- Queue, stack, linked-list inventory, binary-search, and insertion-sort code exists as standalone DSA modules; undo, crafting, and a player-facing puzzle are not implemented.

Do not describe enemy AI/waves, resource gathering, player health, dungeon puzzles, day/night progression, bosses, endings, or high scores as shipped unless later code changes implement them.

## Technical constraints and conventions

- Nullable reference types are enabled; implicit usings are disabled.
- PNG textures are loaded directly with `TitleContainer.OpenStream` and `Texture2D.FromStream`; there is no `Content.mgcb` pipeline.
- The project copies PNG content and `Content/forestmap.tmx` to the build output.
- Preserve map dimensions, required travel locations, collision validation, and connectivity checks when editing map layouts.
- Keep standalone DSA modules distinct from systems wired into the player's experience.
- Preserve existing movement, travel, collision, and rendering behavior unless a task explicitly changes it.

## Build and smoke-check

From the project directory:

```sh
dotnet restore
dotnet build
dotnet run
```

`dotnet run` prints startup DSA and map validation results before opening the game window. No separate test project is currently present; use the build and startup checks as the baseline.

## Development Roadmap & Feature Implementation Schedule

This roadmap outlines the step-by-step implementation plan for the remaining 4-day development window. The final verification pass has been folded into Day 4 so the sprint stays realistic and the rubric remains covered without a separate fifth day.

---

### Milestone 1: World Harvesting, Loot Drops & Inventory HUD (Day 1)
**Primary Focus:** Link $1 \times 3$ arc swing attacks to world tile interactions and dynamic item storage.

* **Target Files:** `TileMap.cs`, `Enemy.cs`, `Game1.cs`, `Inventory.cs`.
* **DSA Module:** Singly Linked List (`Inventory.cs` storing `Item` nodes).
* **Implementation Steps:**
  1. Implement `TryHarvestResource(Point tile, out Item item)` inside `TileMap.cs` to clear trees/rocks/ores and return harvested drops.
  2. Implement `DropLoot()` inside `Enemy.cs` to yield specific drops (e.g., Bones and Gold) when an enemy's HP reaches 0.
  3. Update `Game1.cs` attack evaluation loop so `_player.GetSwingTiles()` invokes resource harvesting and enemy damage simultaneously, appending dropped items into `_inventory.AddItem()`.
  4. Render a bottom-right, Minecraft-style inventory grid in `Game1.Draw()` and show player health and energy bars at the bottom left.
* **Verification:** Swinging at trees, rocks, chests, or sample enemies updates item quantities on the screen HUD.

---

### Milestone 2: Night Phase & Village Hearth Defense (Day 2)
**Primary Focus:** Build the Day/Night state machine and FIFO wave spawner system.

* **Target Files:** `Game1.cs`, `WaveSpawner.cs`, `EnemySpawnInfo.cs`, `TileMap.cs`.
* **DSA Module:** Queue (`WaveSpawner.cs` FIFO `Queue<EnemySpawnInfo>`).
* **Implementation Steps:**
  1. Implement interaction trigger at the Village Hearth (`H` tile in `villagelayout.cs` / TMX) to switch state from `GameState.Day` to `GameState.Night`.
  2. Wire `_spawner.QueueWave(nightNumber)` to populate the wave queue based on the current night (Nights 1 through 5).
  3. Update `WaveSpawner.Update()` to dequeue enemies on a timer, spawning them at village perimeter entry points to march toward the Hearth.
  4. Implement Hearth HP tracking; if all queued enemies are defeated, advance `DayCount` and restore the player to `GameState.Day`.
* **Verification:** Interacting with the Hearth starts the night wave, sequentially dequeues enemies, and successfully transitions back to daytime upon wave completion.

---

### Milestone 3: Village Trader, Crafting & Undo Action Stack (Day 3)
**Primary Focus:** Implement crafting recipe search and LIFO action history refunding.

* **Target Files:** `RecipeBook.cs`, `BinarySearchUtil.cs`, `ActionHistory.cs`, `PlayerAction.cs`.
* **DSA Modules:** Binary Search (`BinarySearchUtil.cs`) & Stack (`ActionHistory.cs`).
* **Implementation Steps:**
  1. Build a basic trader interaction prompt at the Village Trader position.
  2. Wire `BinarySearchUtil.FindByKey()` to look up craftable weapons and armor in `RecipeBook.SortedByCost` based on available inventory resources.
  3. When crafting or trading succeeds, deduct resources from `Inventory` and push a `PlayerAction` onto `ActionHistory` (`_history.Record(...)`).
  4. Wire the **'U'** key to invoke `_history.Undo()`, popping the top action stack record, removing the created item, and refunding the spent materials back to `Inventory`.
* **Verification:** Searching recipes returns exact cost matches, crafting equips new gear, and pressing 'U' instantly undoes the transaction.

---

### Milestone 4: Value Sorting, End Game States, Leaderboard & Final Verification (Day 4)
**Primary Focus:** Add inventory organization, ending triggers, leaderboard sorting, and the full rubric verification sweep.

* **Target Files:** `InsertionSortUtil.cs`, `Inventory.cs`, `Leaderboard.cs`, `Game1.cs`, `DsaDemo.cs`, `Program.cs`, `README.md`.
* **DSA Modules:** Insertion Sort (`InsertionSortUtil.cs`), Graph/BFS connectivity checks (`TileGraph.cs`), and final startup validation `DsaDemo.Run()`.
* **Implementation Steps:**
  1. Wire the **'I'** key to execute `InsertionSortUtil.SortDescending()` on the `Inventory` linked list snapshot, organizing bag items by market value.
  2. Implement game-over state checks:
     * **Victory:** Clearing Night 5 wave queue.
     * **Defeat:** Hearth HP or Player HP dropping to 0.
     * **Evacuation:** Interacting with the secret forest cave gate during a losing night.
  3. Calculate the final run score ($\text{Hearth HP} \times 100 + \text{Gold} \times 10 + \text{Kills} \times 50$).
  4. Pass the final score into `Leaderboard.AddScore()` and run `InsertionSortUtil` to rank top scores.
  5. Run automated DSA checks via `DsaDemo.Run()` at startup, verify all 6 modules (Queue, Stack, Linked List, Binary Search, Insertion Sort, Graph/BFS) with $0$ console errors, and perform a final build run under the .NET 8 DesktopGL profile.
* **Verification:** Pressing 'I' sorts bag contents by value, all 3 game endings log the final score accurately to the sorted leaderboard, and the startup self-check plus build pass cleanly before the game opens.

### Sprint Success Criteria (4-Day Delivery)
- All DSA modules are wired into active gameplay and remain distinct from the underlying game systems.
- The project proves a complete loop: gather resources -> survive nights -> craft/undo -> sort inventory -> end the run with a score.
- Final `dotnet build` and startup `DsaDemo.Run()` validation succeed with no blocking startup errors.
- The game remains playable across the village, forest, and dungeon maps without collision or travel regressions.
